# 恐慌指数 iPhone 小组件 — 可行性评估与技术设计文档

日期：2026-07-21（v2）｜ 范围：美股 (CNN Fear & Greed) + A股/港股 ｜ 商业模式：v1 完全免费 + Tip Jar

**产品一句话**：华人投资者的全球市场情绪仪表盘——美股 CNN 指数 + 自研 A股恐慌指数，一屏对照。

**目标人群**：海外华人投资者（富途/老虎/盈透用户，同时持有美股与 A股/港股/中概股）。他们在非中国区 App Store，**不需要 ICP 备案即可触达**；大陆用户通过 TestFlight 及外区 Apple ID 覆盖。

## 一、可行性评估

### 1.1 市场现状（竞品调研）

App Store 上"Fear & Greed Widget"类应用已有多款，且头部几款**完全免费**：

| 竞品 | 覆盖 | 定价 | 备注 |
|---|---|---|---|
| Fear & Greed Index Widget (2026.4) | 美股 + Crypto | 免费 | 有极值通知，iPhone/iPad/Mac |
| Fear & Greed Index Widgets (Re: Software) | Crypto | 免费 | 实时刷新、仪表盘 UI |
| Fear And Greed Index Widget (Igor Sul, 2022) | Crypto | 免费 | 老牌，评分高 |
| Fear & Greed Index - VIX (2026.5) | 美股 + KOSPI + Crypto | 免费 | 已出现"本土市场差异化"打法 |
| 恐惧指数 - 恐慌与贪婪（中文, 2026） | 美股 + Crypto + 韩股 | 免费 | 中文界面，小组件/锁屏/Watch 全覆盖 |
| FearGreed+（中文, 2025-26） | 美股 + Crypto + 中国 + 日本 | 免费 | 有自定义阈值提醒，最接近的竞品 |

另：乐咕乐股（legulegu.com）网页版已有 A股恐慌贪心指标，验证 A股情绪指数有真实需求，但无小组件形态产品。

**结论：美股/Crypto 赛道已饱和且免费化，中文赛道也已有新品入场**（且都是 2025–2026 的新应用，说明这个方向正在被验证、窗口在收窄）。纯搬运没有生存空间，可攻的点在下节。

### 1.2 差异化定位

竞品是"中文界面的通用指数聚合"，本产品定位为"**华人投资者的双市场情绪仪表盘**"：

1. **自研 A股恐慌指数 + 方法论公开透明**（FearGreed+ 虽有"中国情绪"但数据来源不明；公开七因子合成方法是信任壁垒，也是内容传播素材）
2. 美股 + A股并排对照，服务同时持有两边仓位的华人投资者
3. 面向海外华人的中文体验（这个人群在非中国区 App Store，无备案障碍）

### 1.3 ROI 分析

**成本**

| 项目 | 金额 |
|---|---|
| Apple Developer Program | $99/年 |
| 后端（GitHub Actions + 静态 JSON 托管） | $0 |
| 域名（可选） | ~$10/年 |
| 时间成本 | 约 6–8 周业余时间（详见里程碑） |

**营收策略：v1 不营收**

竞品全面免费 + 首个项目不宜叠加内购复杂度，v1 采用：**完全免费 + Tip Jar（"请我喝咖啡"）**。Tip Jar 是 StoreKit 最简形态（约半天工作量），零门槛吸量的同时顺手走通支付流程。

未来营收留给验证后的方向（M4 之后再评估）：

- 极值提醒推送服务做小额订阅——有真实服务器成本，付费认知合理
- 自研 A股指数数据 API 卖给同类开发者/量化爱好者
- Pro 买断解锁多市场/长历史（届时参考 v1 留存数据定价）

**纯财务 ROI 不高，这是既定事实**。你的目标是"独立开发启动项目 + 自用"，真正的回报在：

- 完整走通 iOS 开发 → 上架 → 收款全流程，这是后续所有项目的复用资产
- 自研指数的数据管道可复用（未来做提醒服务、订阅内容等）
- 自己每天真的会用（自用需求保证你不烂尾）

**评估结论：做。** 但按"3 个月内上架 MVP、不追求完美"的节奏执行，把它当学费最低的第一课。

## 二、技术设计

### 2.1 总体架构

```
┌─────────────────────────────┐
│  数据管道 (GitHub Actions)    │
│  Python + AKShare / 抓取     │
│  cron: 交易时段错峰调度       │
└──────────┬──────────────────┘
           │ 产出 index.json
           ▼
┌─────────────────────────────┐
│  静态托管 (Cloudflare Pages   │
│  或 R2 + CDN)，全球加速       │
└──────────┬──────────────────┘
           │ HTTPS GET (带 CDN 缓存)
           ▼
┌─────────────────────────────┐
│  iOS App (SwiftUI)           │
│  ├─ 主 App：仪表盘/历史图表    │
│  ├─ WidgetKit 小组件          │
│  └─ StoreKit 2 内购          │
└─────────────────────────────┘
```

设计原则：**无服务器、零月费、客户端极薄**。所有指数计算在数据管道完成，App 只消费一个 JSON。这样即使 CNN 端点变动，只改管道，无需发版。

**调度采用交易时段错峰**，而非全天每 30 分钟：A股多数因子（融资融券 T+1 盘后、涨跌停池盘后）盘中不变，CNN 也仅在美股时段更新。建议 A股时段（09:30–15:00 CST）盘中每 30–60 分钟刷宽度/动量/成交类因子、盘后跑一次日结；美股时段（约 21:30–05:00 CST）刷 CNN。**GitHub Actions 定时任务两个坑需注意**：① 调度会有数分钟延迟；② 公开仓库的 scheduled workflow 在仓库连续 60 天无提交活动后会被自动禁用——需加保活提交或定期活动，否则某天会静默停更。

### 2.2 数据源与数据管道

**美股：CNN Fear & Greed**

- 端点：`https://production.dataviz.cnn.io/index/fearandgreed/graphdata`（非官方，需伪装浏览器 UA）
- 由 GitHub Actions 抓取，客户端不直连（避免每台设备被封 + 隐藏不稳定性）
- 兜底：抓取失败时保留上次值并标记 `stale: true`；连续失败 24h 切换为基于 VIX 的简化指数

**A股：自研恐慌指数（核心资产）**

> **为何必须自研（而非复用现成指数）**：A股不存在「像 CNN 之于美股」那样官方权威 + 免费 + 有 API + 稳定的现成恐慌指数——官方「中国波指 iVIX」自 2018-02 停发至今未恢复，中证/上交所也无公开的官方恐贪指数。现存第三方方案均有硬伤：商业 API（聚变智研、国金证券情绪脉冲）付费且黑箱，违背本方案零月费/无服务器/方法论透明三支柱；网页产品（乐咕乐股、百分位）无 API 只能爬取，脆弱且有 ToS 风险。**结论：指数本身自研，但计算逻辑可站在开源肩膀上**（见下）。这一空缺恰恰是本产品「自研 A股指数 = 核心资产」定位成立的原因。
>
> **可复用的开源方法论（M1 参考，加速而非替代）**：
> - `finvfamily/finshare` 的 `FearGreedCalculator`：5 因子加权（涨跌停比 / 融资买入占比 / 北向资金 / 换手率偏离 / 市场宽度）+ 冷启动处理，基于东财公开接口。
> - `hu619340515/a-share-panic-index`：4 因子（波动率 / 涨跌停比 / 股指期货基差 / 南向资金）+ 504 日历史分位 + 动态阈值 + SQLite 持久化，工程完整度高。
>
> 交叉验证：`百分位 baifenwei.com`、`finshare` 独立选出的因子（波动率 / 换手率 / 融资融券 / 市场宽度 / 涨跌停比）与下表高度重合，佐证本因子选择是主流且正确的，且全部可用 AKShare / 东财公开接口免费取到。

参照 CNN 七因子法，用 AKShare（免费、无 token）取数，合成 0–100 指数：

| 因子 | 数据 | 权重 |
|---|---|---|
| 市场广度 | 沪深涨跌家数比（5日平滑） | 20% |
| 涨跌停情绪 | 涨停家数 / (涨停+跌停) | 15% |
| 指数动量 | 沪深300 相对 125 日均线偏离 | 20% |
| 成交热度 | 两市成交额相对 60 日均值 | 15% |
| 新高新低 | 52周新高家数 − 新低家数 | 10% |
| 杠杆情绪 | 融资余额 5 日变化率 | 10% |
| 波动率 | QVIX（`index_option_50etf_qvix`）或自研 50ETF 隐波（反向） | 10% |

> **数据源说明**：波动率因子不能用官方 iVIX（已停发），用 AKShare 的 `index_option_50etf_qvix`（社区复现 QVIX，有历史）或自行按方差互换法从 50ETF 期权链复算。可选第 8 因子：期权 Put/Call Ratio（`option_finance_board`），更贴近 CNN 原版。
>
> **权重为启发式**：上表权重为经验设定，非最优解；v1 先用，后续按历史回测校准。因产品以「方法论透明」为卖点，权重的启发式属性会在 App 内如实标注。

每个因子先算历史分位数（rolling 2 年）归一化到 0–100，再加权平均。历史分位数法可避免绝对阈值调参。**注意：分位数法要求每个因子先回填约 2 年历史**（见 M1 里程碑，回填是独立子任务，工作量不可忽略）。

**港股（Phase 2）**：恒指波指 VHSI + 类似因子合成，MVP 不做。

**产出 JSON 结构**

```json
{
  "updated_at": "2026-07-21T09:30:00+08:00",
  "indices": {
    "us":   { "value": 62, "label": "greed", "prev_close": 58, "week_ago": 45, "stale": false },
    "cn":   { "value": 23, "label": "extreme_fear", "prev_close": 28, "week_ago": 41, "stale": false }
  },
  "history": { "us": [...], "cn": [...] }
}
```

`history` 为近 90 天日频数据，供图表用；单文件控制在 50KB 内。

### 2.3 iOS 客户端

技术栈：**Swift + SwiftUI + WidgetKit + Swift Charts**，最低支持 iOS 17。

**为什么不用 React Native / Flutter（针对前端背景）**：iOS 小组件（WidgetKit extension）只能用 Swift/SwiftUI 编写，RN/Flutter 均不支持（Expo apple-targets 也只是在 RN 项目里嵌 Swift）。本产品核心就是小组件，主 App 只是薄壳——引入 RN 等于为 20% 的部分加一整套框架，核心 80% 照样写 Swift。且 SwiftUI 是声明式框架，`@State`/组件树/单向数据流与 React 心智模型高度同构，对前端开发者学习成本远低于想象；真正的新概念只有 WidgetKit Timeline 机制（见下）。

**项目结构**

```
PanicIndex/
├── App/                 主 App target
│   ├── DashboardView    双市场仪表盘
│   ├── HistoryView      90天历史曲线 (Swift Charts)
│   ├── SettingsView     市场选择、Tip Jar
│   └── IndexRepository  网络 + 缓存 (URLSession, App Group UserDefaults)
├── Widget/              Widget Extension target
│   ├── TimelineProvider 拉取 JSON → 生成 timeline entries
│   ├── SmallWidget      单指数仪表盘
│   ├── MediumWidget     双市场并排 + 7日趋势
│   └── AccessoryWidget  锁屏圆环 (accessoryCircular)
└── Shared/              两 target 共享的模型与取数逻辑 (App Group)
```

**WidgetKit 关键点（新手最容易踩的坑）**

- Widget 不能自主"实时刷新"。用 `TimelineProvider` 返回未来数个 entry，`.after(30分钟)` 策略请求下次刷新；系统实际预算约每天 40–70 次刷新，够用
- App 与 Widget 通过 **App Group** 共享缓存，主 App 刷新后调 `WidgetCenter.reloadAllTimelines()`
- 网络请求放在 `getTimeline` 里做，带 15s 超时，失败则回退缓存值并显示更新时间

**极值提醒**

MVP 用最简方案：主 App 的 `BGAppRefreshTask` 后台拉取 + 本地通知（不保证及时，但零后端成本）。Phase 2 若验证有需求，再上 APNs 推送（需真后端，届时用 Cloudflare Workers + cron 判断阈值），并可作为订阅制付费点。

### 2.4 营收实现 (v1: Tip Jar)

v1 全功能免费。设置页放 Tip Jar（StoreKit 2 消耗型内购，¥6/¥18/¥45 三档"请我喝咖啡"），约半天工作量，用于走通支付与收款全流程。付费墙留到 M4 验证后再设计（见 1.3 节未来营收方向）。

### 2.5 里程碑（按"会编程但没做过 iOS"估计，AI 辅助开发）

| 阶段 | 内容 | 工期 |
|---|---|---|
| M1a 历史回填 | 逐因子回填约 2 年历史（涨跌停池、宽度、融资融券、QVIX 等），落地为分位数计算的基线。AKShare 逐日拉取需限频重试，是独立且易被低估的子任务 | 3–5 天 |
| M1b 数据管道 | Python 脚本：CNN 抓取 + A股七因子合成 + GitHub Actions 错峰产出 JSON。可参考 finshare / a-share-panic-index。**这步你用现有技能就能完成，先做，出成果最快** | 1–2 周 |
| M2 App MVP | SwiftUI 仪表盘 + Small/Medium Widget + 缓存。跟着 Apple 官方 SwiftUI/WidgetKit 教程 + AI 辅助 | 2–3 周 |
| M3 打磨上架 | 历史图表、锁屏组件、Tip Jar、App Store 素材（中英双语）、审核 | 2 周 |
| M4 验证期 | TestFlight 分发国内用户 + 美区上架，收集数据 4 周，再决定是否做 ICP 备案进中国区 | 4 周 |

总计约 6–8 周业余时间到上架。

### 2.6 验证指标（M4 结束时回答）

- 7 日留存 > 30%？（自用型工具的及格线；TestFlight + 正式版合并看）
- 海外华人渠道（小红书/即刻/Twitter 中文圈）是否有自然传播/自发讨论？
- 你自己是否每天还在看它？

三项中两项达标 → 投入备案进中国区，并设计正式付费墙；否则保持现状作为作品集 + 自用工具，成本仅 $99/年。
